Private transport contract:
- `airplay/private_trial_transport` is private-profile-only and requires `SYSTEM_MANAGE`. It is not a general playback API or live-adoption approval.
- Closed `request` variants: `arm` has exactly `mode`, `attempt_id`, `player_id`, `media`; `play`, `stop`, `get` have exactly `mode`, `attempt_id`. Tokens are 32 lowercase hexadecimal characters. Unknown keys, types, modes and tokens fail closed.
- ARM requires one exact admitted TV/player/queue, no current stream, grouping, bridge or protocol redirect, no implicit receiver writes, disabled experimental flags and a current attested ready strict-peer PTP child. The provider, admission epoch and player/queue objects remain bound throughout start.
- `media` is bound once at ARM: a numeric, non-loopback, non-multicast IPv4 HTTP URI, explicit unprivileged port, exact `/stimulus.wav` path, maximum 256 characters, no userinfo/query/fragment. PLAY cannot replace it, choose options, sort, resume, change volume or retry. The actual queue call is HTTP/no-sort/replace.
- The server validates URI syntax, not the resource's waveform, duration, hash, redirects or receiver buffering. A caller must own the fixed finite low-amplitude stimulus server, serve only the independently hashed stimulus and not redirect it. This route adds no network fetch beyond the existing privileged queue path. URI syntax is NOT finite-content proof or an SSRF protection for a malicious `SYSTEM_MANAGE` principal.

Deadline and clock contract:
- ARM commits ownership and its watchdog before acknowledgement. All server deadline arithmetic uses the same event-loop monotonic clock. Cancellation is due at arm + 1.75 seconds, natural drain at arm + 4.75 seconds, containment/reap observation at arm + 5 seconds. PLAY and duplicate requests never restart these timers.
- Receipt of a valid ARM acknowledgement causally follows server arming. PLAY dispatch follows acknowledgement, so the fixed server observation deadline is no later than PLAY dispatch + 5 seconds in elapsed time. No client/server monotonic numbers are compared. OS starvation is not bounded by this software contract.
- Future private client integration must measure the entire ARM round trip and subsequent local elapsed time conservatively, including a clock-rate/scheduling allowance. Dispatch only with at least 250 ms cancellation headroom; late/lost ACK means no PLAY and no retry. Require 5.25 seconds of the existing main budget remaining after ACK, without rebasing it or borrowing clear reserve.
- The client must independently arm attempt-scoped STOP before PLAY, dispatch it at its conservative origin + 1.75 seconds, and reserve three seconds HTTP allowance plus 250 ms margin. This client integration is not in this PR. Dropped STOP/PLAY responses cannot disarm the server watchdog. An HTTP timeout means completion unknown, not cessation.

Ownership and outcomes:
- One PLAY, one exact session/stream and one START generation per admission epoch. Completed/expired attempts remain tombstones. No reuse while old spawn/cleanup ownership is unresolved. A validated matching admission mutation revokes synchronously before leaf mutation/persistence; refused CLEAR does not cancel an owner. Unload revokes before shutdown awaits. Neither adds a cleanup wait to CLEAR.
- STOP synchronously revokes and cancels the owned start task before any controller/provider lock. Repeated STOP joins one cleanup. The ContextVar exists only around the real queue call; lower session/stream objects capture it explicitly. Guards surround queue/provider locks, publication, connection, audio feeding, child spawn and FIFO START delivery.
- Process wrappers and shielded spawn tasks are retained before awaiting creation. Late children cannot publish or START and remain owned for cleanup. Cleanup uses captured references and preserves foreign/newer publications. Each captured process wrapper's stderr reader, including one created by a late FFMpeg start, is cancelled and joined before raw pipe consumption. Reader release does not delay the independent absolute forced-signal boundary.
- `natural-cleanup` means the observed owned software resources drained without a forced signal inside the fixed window. `forced-containment` is never a normal-stop pass. `incomplete` means the observation window or cleanup failed. Final reaping continues under retained ownership after a missed window and can never turn that miss into success. Arbitrary OS starvation, unreturned spawn or uninterruptible processes cannot be guaranteed reaped within five seconds.
- Response facts are software ownership facts only. They do not establish acoustic cessation, receiver buffer flush, stimulus delivery, RTP/audio bytes, peer-clock correctness, relay ownership, loudness or native controls. Actual-write telemetry is separate work.
