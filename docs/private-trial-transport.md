Private transport contract:
- `airplay/private_trial_transport` is private-profile-only and requires `SYSTEM_MANAGE`. It is not a general playback API or live-adoption approval.
- Closed `request` variants: `arm` has exactly `mode`, `attempt_id`, `player_id`, `media`; `play`, `stop`, `get` have exactly `mode`, `attempt_id`. Tokens are 32 lowercase hexadecimal characters. Unknown keys, types, modes and tokens fail closed.
- ARM requires one exact admitted TV/player/queue, no current stream, grouping, bridge or protocol redirect, no implicit receiver writes, disabled experimental flags and a current attested ready strict-peer PTP child. The provider, admission epoch and player/queue objects remain bound throughout start.
- `media` is bound once at ARM: a numeric, non-loopback, non-multicast IPv4 HTTP URI, explicit unprivileged port, exact `/stimulus.wav` path, maximum 256 characters, no userinfo/query/fragment. PLAY cannot replace it, choose options, sort, resume, change volume or retry. The actual queue call is HTTP/no-sort/replace.
- The server validates URI syntax, not the resource's waveform, duration, hash, redirects or receiver buffering. A caller must own the fixed finite low-amplitude stimulus server, serve only the independently hashed stimulus and not redirect it. This route adds no network fetch beyond the existing privileged queue path. URI syntax is NOT finite-content proof or an SSRF protection for a malicious `SYSTEM_MANAGE` principal.

Deadline and clock contract:
- ARM commits ownership and its watchdog before acknowledgement. All server deadline arithmetic uses the same event-loop monotonic clock. Cancellation is due at arm + 1.75 seconds, natural drain at arm + 4.75 seconds, containment/reap observation at arm + 5 seconds. PLAY and duplicate requests never restart these timers.
- Receipt of a valid ARM acknowledgement causally follows server arming. PLAY dispatch follows acknowledgement, so the fixed server observation deadline is no later than PLAY dispatch + 5 seconds in elapsed time. No client/server monotonic numbers are compared. OS starvation is not bounded by this software contract.
- Future private client integration must measure the entire ARM round trip and subsequent local elapsed time conservatively, including a clock-rate/scheduling allowance. Dispatch only with at least 250 ms cancellation headroom; late/lost ACK means no PLAY and no retry. Require 5.25 seconds of the existing main budget remaining after ACK, without rebasing it or borrowing clear reserve.
- The client must independently arm attempt-scoped STOP before PLAY, dispatch it at its conservative origin + 1.75 seconds, and reserve three seconds HTTP allowance plus 250 ms margin. This client integration is not in this PR. Dropped STOP/PLAY responses cannot disarm the server watchdog. An HTTP timeout means completion unknown, not cessation.

Ownership and outcomes:
- One PLAY, one exact session/stream and one START generation per admission epoch. Completed/expired attempts remain tombstones. No reuse while old spawn/cleanup ownership is unresolved. A validated matching admission mutation revokes synchronously before leaf mutation/persistence; refused CLEAR does not cancel an owner. Unload revokes before shutdown awaits. Neither adds a cleanup wait to CLEAR.
- STOP synchronously revokes and cancels the owned start task before any controller/provider lock. Repeated STOP joins one cleanup. The ContextVar exists only around the real queue call; lower session/stream objects capture it explicitly. Guards surround queue/provider locks, publication, connection, audio feeding, child spawn and FIFO START delivery.
- Process wrappers and shielded spawn tasks are retained before awaiting creation. Late children cannot publish or START and remain owned for cleanup. Cleanup uses captured references and preserves foreign/newer publications. FIFO creation is shielded and retained until its worker finishes; cleanup joins that task before unlinking, so cancellation cannot leave a late-created FIFO behind. Each captured process wrapper's stderr reader, including one created by a late FFMpeg start, is cancelled and joined before raw pipe consumption. Reader release does not delay the independent absolute forced-signal boundary.
- `natural-cleanup` means the observed owned software resources drained without a forced signal inside the fixed window. `forced-containment` is never a normal-stop pass. `incomplete` means the observation window or cleanup failed. Final reaping continues under retained ownership after a missed window and can never turn that miss into success. Arbitrary OS starvation, unreturned spawn or uninterruptible processes cannot be guaranteed reaped within five seconds.
- Response facts are software ownership facts only. They do not establish acoustic cessation, receiver buffer flush, stimulus delivery, RTP/audio bytes, peer-clock correctness, relay ownership, loudness or native controls. Actual-write telemetry is separate work.

V2 media receipt (`airplay/private_trial_transport_v2`):
- A second command with the same closed request keys, scope and validation as v1, selected by command name, never by a request field. Both commands share the one-attempt tombstone/admission guard. The version is stored at ARM; `get`/`play`/`stop` through the other command, or a second ARM, are refused with no side effect. v1 is byte-schema unchanged and cannot satisfy audio evidence. No fallback exists if v2 is absent.
- ARM v2 captures the admitted player's canonical numeric IPv4 address and refuses anything else. That held address, not the child's echo, is what the receipt is compared with.
- The snapshot is the eight v1 fields with `version` 2 plus `media` with exactly `state`, `route`, `epoch`, `fresh_units`, `fresh_bytes`. `pending` and `incomplete` carry route `unknown` and null epoch/counts. `complete` carries route `raop|compat|udp`, epoch 1 and counts in 1..4294967295. `incomplete` is terminal and never upgrades. Pending latches `incomplete` at `observe_at`; so do a forced kill, a final after `observe_at`, and any rejected, replaced, truncated or oversized receipt. `complete` is sender-write evidence only; it never turns forced or late cleanup into success. A pass needs both valid media and natural cleanup within their own deadlines (+4.75 natural drain, +5 observation, +1.75 cancellation, all unchanged).
- Only a v2 attempt passes `--private-media-receipt` to the qualified private child. An older CLI rejects the flag and the attempt fails closed; nothing retries without it.
- The v2 stream is the sole stdout owner through STOP, release and EOF: no competing `readline`, raw drain or `communicate`. After the unchanged first attestation, `TrialAsyncProcess.read_receipt_chunk` (1..1024 bytes, no `_close_called` shortcut) hands screened bytes to `ReceiptScanner`: a line-start `[ATTEST]` (also split across chunks) revokes trust and signals the child once before any of its bytes are exposed; `close`/`kill` before EOF contain the child without reading stdout. Caps: 64 KiB total, 512 bytes per `@MEDIA` line, 4096 per ordinary line. Anything media-looking is diverted from every logger, and a malformed or capped receipt discards to EOF and is incomplete.
- The final record is held and counts only at EOF with the exact historical (non-revoked, not necessarily live) child, the captured stream and attempt, one claimed START, receipt route equal to the route parsed from `[STATUS] route` (`raop` = legacy, `compat` = `raop-compat`, `udp` = native unbuffered, `buffered` never qualifies), address equal to the held target, port equal to the `setup_port` the same record reports (the child's own parsed SETUP port; same-trusted-child evidence, not independent observation), epoch 1, no fault or overflow, and no byte after the record. Idle and backlog counts are additional, not invalid.
- Limits: counts are the child's kernel write acceptance, not egress, receiver playback or acoustics; the child's own scalars are same-trusted-child evidence, not independent packet observation. Buffered TCP is unsupported. A new v2 client, parser and source inventory are a separate successor; the accepted v1 client and inventory are untouched.

- If the stdout owner is lost before EOF (cancel, parser or start-mode exception), the attempt rejects the receipt and signals the child at once (an owner cancelled before its first step is contained by `_drain`, within the unchanged deadlines), then, only after the owner is joined (no competing reader), discards stdout to EOF and reaps. A child writing more than the pipe buffer therefore cannot strand cleanup. Deadlines are unchanged.
- A v2 attempt never owns native volume capture. ARM requires every private flag off and `check_current` re-checks them, but `connect` computes capture eligibility before its awaits, so a flag set and cleared again in between passes `check_current` with stale eligibility. A v2 `connect` that computed capture eligible therefore refuses (`capture-refused` stop, `ValueError`) before the FIFO or child exists. v1 is unchanged.
