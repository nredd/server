# Private bounded TV RAOP transport controller

`scripts/private_tv_transport.py` is private trial tooling layered on the existing
`tv-raop` admission scope. It does not change target admission, binary pins,
provider flags, pairing, receiver volume, native grouping, or the admission-only
window wizard.

The controller accepts only a validated `tv-raop` inventory from
`scripts/private_trial_scope.py`, checks that exactly its Apple TV player is
registered, and uses MA's supported authenticated API. Supply the short-lived API
token through an inherited environment variable (default `MA_TOKEN`); the script
never writes, logs, or places it in a receipt.

It generates exact local WAV bytes: 44.1 kHz, stereo, 16-bit, 440 Hz for three
seconds at -45 dBFS, followed by one second of digital silence. The receipt carries
the generated byte count and SHA-256. A one-route local HTTP server binds only to
an explicit IPv4 address and ephemeral port. Its advertised IPv4 address is also
explicit. It serves only `/stimulus.wav`. The receipt's `completed_fetches` counts
requests whose whole body was written to the socket, measured from that server and
not assumed from a successful MA API request. It does not say whether a fetch was a
metadata probe (e.g. `ffprobe`) or the PCM read, and it identifies only a client
fetch, not Music Assistant's requester identity.

Time budget: `OBSERVATION_SECONDS` is 6s, the 4s wave plus 2s for MA play latency,
any early metadata fetch, and receiver start. The final `HTTP_TIMEOUT_SECONDS` (3s)
are reserved for the stop request, so the whole budget is 9s from before arming. The
controller never stops on a fetch, because the first one can be a metadata probe that
lands well before playback. It observes until the reserved stop deadline, then stops.

Before its one `player_queues/play_media` request, the controller spawns a
one-shot detached `emergency-stop` process. That process waits on a monotonic
clock until a full bounded stop-request interval remains, then sends
`players/cmd/stop` at that reserved point even if the parent is stuck in an accepted
playback response.
The parent also attempts the same idempotent stop in `finally`; its result is
receipt evidence, not the safety guarantee. Every MA HTTP operation has one
absolute timeout covering connection, headers and body transfer, so a slow-drip
response cannot extend the budget. It requires an already armed
`private_dev_lifecycle.py` run and verifies its live lease before dispatch; that
independent lifecycle watchdog remains the recovery authority if either
transport process fails.

The receipt remains `INCOMPLETE`: MA acceptance, the completed-fetch count, and
a stop request are independently recorded facts, not transport acceptance. A clean
incomplete receipt exits `2`; `FAILED`, any recorded error, or a missing stop request
exits `1`. The controller has no `0` acceptance exit while receiver evidence is
missing. It never claims child `connected`, PCM arrival, RTP, receiver group
membership, audible output, or iPhone controls. No packet capture is created,
accepted, or synthesized by this tool.

This is controller infrastructure, not receiver acceptance or a deployment recipe.
Run it only from the intended private host after the parent has supplied the
lifecycle run, inventory, explicit bind/advertised addresses, API endpoint, and
short-lived credential. Do not add household identifiers to this repository.

## No implicit receiver writes

On the private trial target an Apple TV player sends nothing to the receiver that was not
explicitly commanded:

- The connect-time `VOLUME` push, its 2 second repeat and the bridge's initial-volume retry are
  suppressed, including a latched mute, so the receiver's own level is never persisted over.
- Playback no longer wakes the device through Companion `turn_on`, and a `stop` with no active
  stream no longer sends Home. Explicit `power`, `wake`, `volume_set` and `volume_mute`
  are unchanged. Explicit `play` is still sent but no longer wakes a sleeping TV first.
- The receiver's DACP volume echo is already ignored for every Apple device
  (`AirPlayPlayer.ignore_volume_reports`), so it never writes `VOLUME` back to a TV.
- HomePods, other receivers and non-trial profiles keep today's behavior.

Limit: a latched mute is not sent, so a stream can start silent while the player state still
says muted, and the receiver's mute state can remain unknown. The caller must abort actual
transport when the player is known to be muted.
